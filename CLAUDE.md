# Scenario Analysis Tool v3

A free, public, browser-only tool from Granular Energy. Users build a portfolio of consumers and generators (from a built-in library or their own CSVs), allocate generation to consumers with a percentage matrix, and see their hourly matching score computed the way the Granular platform computes it (as-consumed allocation with shape preservation). Scenarios can be saved and compared side by side.

Read `process/research/project-plan.md` for the full product decisions and `process/research/engine-spec.md` for the matching algorithm. The plan is the source of truth for scope; do not add features it lists as out of scope.

## Tech stack

- React 19 + TypeScript (strict), Vite 8
- Highcharts 13 via `highcharts-react-official` (commercially licensed; use the npm package directly)
- PapaParse for CSV, html2canvas + jsPDF for PDF export
- Vitest for unit tests, Playwright for end-to-end tests
- No backend. Deployed to Vercel. All state lives in the browser (localStorage).

## Non-negotiables

- **Engine parity.** `src/engine` must reproduce `src/engine/fixtures/revolt-golden.json` within 1e-6 relative tolerance. Those numbers come from the Granular platform's allocation engine. If a test against the fixtures fails, the engine is wrong, not the fixture.
- **Typical year.** Built-in data has 8,760 hourly slots (1 Jan 00:00 to 31 Dec 23:00, non-leap, local clock time, no DST, no real year). Uploads are mapped onto these slots; see `process/research/engine-spec.md` section 4.
- **Pure engine.** Nothing in `src/engine` imports React, DOM APIs, or anything from `src/components` or `src/state`.
- **Limits.** Max 5 consumers and 5 generators per portfolio. Compare up to 4 scenarios.
- **Gated downloads.** PDF downloads require the HubSpot form to have been submitted (remembered in localStorage). The scenario `.json` download is not gated.

## Coding standards

- TypeScript strict; no `any`; prefer `readonly` arrays for engine inputs.
- Functional components with hooks. One responsibility per component; keep components under ~150 lines.
- Pure functions in `src/engine` and `src/io`; all of them unit tested.
- Energy-domain names: `consumer`, `generator`, `allocatedMWh`, `matchedMWh`, `excessMWh`, `unmatchedMWh`, `hourlyScore`, `annualScore`, `matchingGranularity`.
- Use `useMemo` for engine runs; the engine must stay under 50 ms for a 5×5 portfolio on a laptop.
- Charts: all Highcharts config lives in `src/components/**/charts/*.ts` as plain config builders, tested where logic exists (series shaping), with thin React wrappers.
- British English in UI copy and comments. No exclamation marks in UI copy.
- Comments explain why, not what.

## Design system

Follow `process/research/design-system.md` (Granular tokens: Inter body, Space Grotesk titles, teal `#00988B` as the only accent, off-white `#FBFAF9` page, white cards with `#E3E0DD` borders, platform technology colours). Tokens are CSS variables in `src/styles/tokens.css`; never hard-code colours in components.
