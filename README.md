# Scenario Analysis Tool v3

Granular Energy's free hourly matching estimator: build a portfolio of consumers and generators, allocate generation with a percentage matrix, and see the hourly matching score computed the way the Granular platform computes it. Save scenarios and compare them side by side.

## Getting started

```bash
# Install dependencies
npm install

# Start the dev server
npm run dev        # http://localhost:5173

# Run unit tests (including platform-parity golden fixtures)
npm test

# Type-check
npm run typecheck

# Lint
npm run lint

# Build and run end-to-end tests
npm run build && npm run test:e2e
```

The app loads a demo portfolio on first visit: one Data centre consumer (50,000 MWh) with Solar PV temperate and Wind onshore temperate generators, both allocated 100 % at hourly granularity.

## Deployment

The app is deployed to [scenarios.granular-energy.com](https://scenarios.granular-energy.com) via Vercel.

To deploy:

1. Push the branch to GitHub.
2. Vercel automatically builds and deploys from the `main` branch.
3. The build command is `npm run build` (runs `tsc -b && vite build`).
4. The output directory is `dist/`.
5. No environment variables or backend configuration are needed — the app is entirely client-side.

Preview deployments are created automatically for pull requests.

## Profiles

Built-in profiles live in `src/data/profiles/`. Each is a JSON file with a `data` array of 8,760 normalised hourly values (sum ≈ 1.0), representing a typical non-leap year (1 Jan 00:00 to 31 Dec 23:00).

The profile registry at `src/data/profiles/registry.json` lists all available profiles with metadata:

- **Consumption profiles** (`consumption` array): `id`, `file` (path relative to the profiles directory), and `defaultAnnualMWh`.
- **Generation profiles** (`generation` array): `id`, `file`, `technology` (determines chart colour), `capacityFactor`, and `defaultCapacityMW`.

To add or update a built-in profile:

1. Place the normalised JSON file in the appropriate subdirectory (`consumption/` or `generation/`).
2. Add or update the entry in `registry.json` with the correct metadata.
3. Add a human-readable display name in `src/state/profileLoader.ts` (`DISPLAY_NAMES` map).
4. Run `npm test` to verify nothing breaks.

## Golden fixtures

`src/engine/fixtures/revolt-golden.json` contains reference results generated by the Granular platform's allocation engine (revolt `CoreAllocationEngine` with `GreedyAllocationStrategy`). The TypeScript engine in `src/engine/` must reproduce these numbers to 1e-6 relative tolerance.

To regenerate the golden fixtures from the revolt repo:

```bash
# In the revolt repository
poetry run python working_dir/scenario_tool/generate_golden_fixtures.py ~/path/to/scenario-analysis-tool-v3
```

This script runs the platform engine on the same built-in profiles and writes the results to `revolt-golden.json`. After regeneration, run `npm test` in this repo to confirm the TypeScript engine still matches.

**Do not edit `revolt-golden.json` manually.** If a golden test fails, the engine implementation is wrong, not the fixture.

## How it is built

The project is developed with a planner → generator → evaluator loop of Claude Code agents (`process/scripts/harness.sh <milestone>`), with milestone briefs in `process/plans/`, research docs in `process/research/`, and human findings in `process/FEEDBACK.md`. See `CLAUDE.md` for the rules every agent follows.
