# Milestone M3: Results tab

## Scope

Build the Results tab so that users can explore matching results for the current portfolio. The tab has a header (granularity description, consumer selector, four score/metric tiles), five Highcharts charts (average 24-hour profile, hourly matching heatmap, monthly breakdown, example day picker, Sankey), and an empty state when no allocation exists. All data comes from the memoised `engineResult` already computed in `PortfolioContext`; switching the consumer selector filters the view without re-running the engine. The tab must be usable at 375 px viewport width.

## Out of scope

- Saving or loading scenarios (M4)
- Compare tab content (M4)
- PDF report and HubSpot gate (M4)
- Design polish beyond correct use of tokens, accessibility pass, Vercel deploy (M5)
- Any new engine logic — the engine is complete and must not be modified

## Notes for the generator

1. **Engine result is already available.** `usePortfolioContext()` exposes `engineResult: EngineResult | null`. This contains `portfolio: MatchingSummary` and `consumers: ConsumerResult[]` with all the data needed for tiles and charts. The consumer selector should index into `engineResult.consumers` by `consumerId`; switching consumers is a local UI filter, not an engine call.

2. **Generator contributions per consumer.** Each `ConsumerResult` has a `generators: GeneratorContribution[]` array with per-generator hourly and monthly allocated/matched MWh. Use these for the per-technology stacked bars in the average-day, monthly, and example-day charts.

3. **Generator utilisation for the Sankey.** `engineResult.generators: GeneratorUtilisation[]` gives `totalGenerationMWh`, `allocatedMWh`, `unallocatedMWh`, and `allocatedByConsumer` per generator — exactly the data needed for Sankey flows.

4. **Chart config builders.** Per `CLAUDE.md`, Highcharts configuration should live in `src/components/results/charts/*.ts` as plain functions that accept engine data and return Highcharts options objects. These are testable without React. Thin React wrappers call the builders and render `<HighchartsReact />`.

5. **Average 24-hour profile.** Compute by averaging each of the 24 hour-of-day slots across all 365 days: for hour `h`, average = `Σ_{d=0..364} series[d*24 + h] / 365`. Do this for demand, per-generator allocation, and unmatched.

6. **Heatmap data.** For each (month, hour) cell, aggregate the `hourlyMatchPct` values for all hours in that month at that hour-of-day, then average them. The result is a 12×24 matrix of percentages (0–100).

7. **Example day.** Day index `d` maps to hourly slots `d*24` through `d*24 + 23`. Default to 1 May = day index 120 (31 Jan + 28 Feb + 31 Mar + 30 Apr = 120). Provide a date picker or day-of-year selector.

8. **Feedback from FEEDBACK.md.** Priya's feedback says the annual score was confusingly placed near a chart. Place both scores side by side in the tiles header area, clearly labelled. The header must also state the matching granularity (also Priya's feedback about shape preservation clarity).

9. **Hourly granularity special case.** At hourly granularity, `annualScore === hourlyScore` and `totalExcessMWh === 0` because allocation never exceeds demand in any single hour. This is correct behaviour, not a bug. Monthly and annual granularities will produce non-zero excess.

10. **Sankey at portfolio level vs consumer level.** For "Whole portfolio", the Sankey shows all generators → all consumers → matched/excess. For a single consumer, it shows only the generators allocated to that consumer → that consumer → matched/excess. Use `GeneratorUtilisation.allocatedByConsumer` and `ConsumerResult` data accordingly.
