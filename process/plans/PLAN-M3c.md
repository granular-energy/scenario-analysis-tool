# Milestone M3c: "As produced" method and shape-preservation explanation

## Scope

Add a fourth matching method, "As produced (no cap)", to the engine and UI. In this method the consumer receives its full matrix share of each generator's hourly output with no capping at demand in any window, so excess appears wherever generation exceeds consumption in the hour. The engine type, allocation logic, golden-fixture parity tests, granularity selector, and Results header all update. Separately, all four method descriptions gain explicit wording about the cap window and shape preservation, and a new "How allocation works" note appears on the Allocation tab.

## Out of scope

- A mode without shape preservation.
- Changes to the three existing capped methods' engine logic or golden fixture values.
- Scenarios, Compare, PDF, HubSpot (M4).
- New chart types.

## Notes for the generator

- The golden fixture file already contains `as-produced` result sets. The generator should **not** edit `revolt-golden.json` by hand.
- The golden test (`src/engine/__tests__/golden.test.ts`) currently has a `SUPPORTED_GRANULARITIES` guard that skips `as-produced` fixture entries because the engine doesn't handle them yet. Once the engine supports `as-produced`, **remove the guard and the `SUPPORTED_GRANULARITIES` array** so the test iterates over all granularity keys in the fixture (including `as-produced`). The `TODO(M3c)` comment marks the location.
- The `allocateToConsumer` function in `src/engine/allocate.ts` currently caps allocation at `remaining` demand within each window. For `as-produced`, skip the capping: assign each generator's full supply share to the consumer. One clean approach is to add a code path for `'as-produced'` in `allocateToConsumer` (or in `windowsFor`) that simply copies the supply into the allocation array without the `min(available, remaining)` step. The `summarise` function in `score.ts` already computes matched/excess/unmatched correctly from any allocation series.
- The existing `windowsFor` function returns windows for hourly/monthly/annual. For as-produced, a single year-wide window with no demand cap is one option; alternatively handle it as a special case before the window loop. Either way, the key difference is: no `min(available, remaining)` and no `remaining -= quantity`.
- The `granularityLabel` helper, any `Record<MatchingGranularity, ...>` maps, and every `switch` on granularity must gain the `'as-produced'` case — `npm run typecheck` will catch missing cases if the type is a union.
- The Results header currently shows just the label (e.g. "Hourly matching only"). It needs to expand to the full `"label · cap rule · shape rule"` string as specified. Consider a new helper or extending `granularityLabel` to return a richer object.
- The "shape preserved" tooltip should be implemented as an inline element with `title` or a CSS tooltip on hover; keep it accessible (e.g. a `<button>` or `<abbr>` with `aria-label`).
- The BRIEF-M3c.md specifies exact copy for the "How allocation works" note and the as-produced description. Reproduce it verbatim.
- The `PortfolioState.granularity` field and the `SET_GRANULARITY` action already accept `MatchingGranularity`, so they will accept `'as-produced'` once the type is widened. Ensure localStorage persistence round-trips the new value correctly.
