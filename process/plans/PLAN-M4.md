# Milestone M4: Scenarios, Compare and Reports

## Scope

Add the ability to save the current portfolio as a named scenario, list/rename/delete saved scenarios, and load one back into the builder. Add scenario file export (`.json`, ungated) and import with validation. Build the Compare tab so the user can pick up to 4 saved scenarios and see tile columns, an overlaid monthly score chart, an assumptions diff table, and a per-consumer score table. Build both a single-scenario PDF report and a comparison PDF using html2canvas + jsPDF. PDF downloads are **ungated** in this milestone (the HubSpot gate is deferred; keep download entry points easy to wrap later). Use "allocation method" (not "matching granularity") in all new user-facing copy.

## Out of scope

- HubSpot form / lead-capture gate (may be added in a later milestone; keep download call sites easy to wrap)
- Hourly CSV export
- Backend storage or accounts
- Design-system polish pass, accessibility audit, Vercel deploy (M5)
- Changes to the matching engine

## Notes for the generator

- **No HubSpot gate.** The brief explicitly defers gating. Keep PDF download call sites in a thin wrapper so a gate can be inserted later, but do not implement the gate or modal.
- **Allocation method naming.** The brief (context section) mandates "allocation method" with options "as produced", "annual target", "monthly target", "hourly only". Use these labels consistently in Compare tables and PDFs. The `MatchingGranularity` type (`'hourly' | 'monthly' | 'annual' | 'as-produced'`) maps to those labels.
- **annualScore is volumetric and can exceed 100 %.** Display `MatchingSummary.annualScore` as-is; do not cap or recompute.
- **Scenario storage schema.** A saved scenario should include everything needed to restore the builder state and display Compare tiles without re-running the engine: portfolio state (consumers with shapes, generators with shapes, matrix, granularity) plus a results summary snapshot (the four tile values and monthly scores). The `.json` export is self-contained (embedded shapes).
- **Playwright config.** The `webServer` in `playwright.config.ts` builds before serving. Never start a separate preview on port 4173. E2e tests should use the existing config.
- **Demo portfolio golden numbers.** Hourly granularity: hourly score 67.33 %, annual score 100.74 %, excess 0 MWh, unmatched ≈ 16 335 MWh, total demand 50 000 MWh, total generation assigned ≈ 50 370 MWh. Consumer "Data centre" scores are the same as portfolio (single consumer). These numbers come from the `revolt-golden.json` fixtures and the demo portfolio definition.
- **Compare series colours.** The brief references `--ge-series-1..4`. If these tokens do not yet exist in `tokens.css`, define them (e.g. teal-700, hydro blue, biomass green, solar yellow — consistent with the general palette in the design system).
- **PDF rendering.** Use html2canvas + jsPDF as specified in CLAUDE.md. Render from a hidden print-layout React tree, not by screenshotting the interactive UI. Charts rendered via Highcharts should use `chart.exportChart` or be captured in-DOM.
- **Existing tabs.** The Compare tab currently renders a placeholder div (`data-testid="compare-placeholder"`). Replace it with the full Compare view. The TabBar already includes the "Compare" tab.
