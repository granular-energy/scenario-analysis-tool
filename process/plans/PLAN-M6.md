# Milestone M6: HubSpot sign-up gate

## Scope

Add a full-screen sign-up gate that blocks the entire app on first visit. The gate renders a modal over the blurred, non-interactive tool containing a HubSpot embedded form (v2 embed script, EU region). On form submission (or via a development-mode bypass button when the form ID is a placeholder), the gate is dismissed and a `localStorage` flag is set so returning visitors are not asked again. A `?signedUp=1` query parameter also sets the flag for internal demos. If the HubSpot script fails to load within 5 seconds, the modal shows a fallback message with a contact link and keeps the tool locked. A `src/config.ts` module centralises HubSpot configuration. All existing e2e tests are updated to set the signed-up flag before each test so the gate does not block them. PDF downloads remain ungated (the whole-app gate replaces any per-download gate).

## Out of scope

- Server-side verification of form submissions
- Accounts or authentication
- Storing submitted data anywhere other than HubSpot
- Changes to the matching engine, existing tabs, or chart rendering
- Actual HubSpot form ID (a placeholder is used until marketing supplies it)

## Notes for the generator

- **localStorage key.** The brief specifies `scenario-tool.signedUp` as the key (with a dot, not the `sat-v3-` prefix used by the portfolio/scenario stores). Follow the brief exactly.
- **Existing e2e tests clear localStorage.** Every existing spec calls `localStorage.clear()` in its `beforeEach`. After that clear, the sign-up flag is gone, so the gate would block the test. Add `localStorage.setItem('scenario-tool.signedUp', new Date().toISOString())` immediately after each `localStorage.clear()` call (or after the initial `page.goto('/')` if the clear happens via `page.evaluate`). The flag must be set before the page navigates or reloads, so use `page.evaluate` before navigation or `page.addInitScript` to inject it.
- **Playwright webServer.** The config builds before serving and sets `reuseExistingServer: false`. Do not start a separate preview server on port 4173 during tests.
- **HubSpot form submission callback.** When `isHubSpotConfigured()` is `true`, the HubSpot embed's `onFormSubmitted` callback should set the localStorage flag and close the modal exactly as the dev-mode button does. This path cannot be e2e tested with the placeholder form ID, but the shared state logic should be unit-tested.
- **5-second timeout.** Use a timer (e.g. `setTimeout`) that fires 5 seconds after the HubSpot embed script element is injected. If the form has not rendered by then, show the error fallback. Clear the timer if the form renders successfully.
- **Focus trap.** A simple focus-trap implementation is sufficient (intercept Tab and Shift+Tab keydown events at the modal boundary). No need for a third-party library.
- **Blurred background.** Apply `filter: blur(4px)` and `pointer-events: none` to the main app container while the gate is active. Remove when dismissed.
- **No per-download gate.** The CLAUDE.md mentions "Gated downloads: PDF downloads require the HubSpot form to have been submitted". M6 replaces this with a whole-app gate. Remove any per-download gate logic if it exists; PDF and JSON downloads should work freely once the user is past the sign-up gate.
