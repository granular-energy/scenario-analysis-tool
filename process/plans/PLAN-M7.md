# Milestone M7: "Set % of consumption" allocation mode

## Scope

Add a second way to fill the allocation matrix, chosen by a segmented toggle on the Allocation tab. The existing default ("Share of generator output") is unchanged. The new mode ("Set % of consumption") lets the user specify what percentage of each consumer's annual demand is supplied by each generator's normalised hourly shape, ignoring the generator's own library sizing. The engine, state, Allocation tab, score strip, Results tab header, scenario IO, Compare assumptions table, and both PDFs are updated to support the new mode. Both matrices are persisted independently so toggling between modes loses nothing.

## Out of scope

- Changes to the matching methods (hourly / monthly / annual / as-produced behaviour)
- New library profiles or profile shapes
- Any change to generator-share allocation behaviour or existing golden fixture results
- Changes to the sign-up gate, HubSpot integration, or CTA band

## Notes for the generator

- **Backward compatibility is paramount.** The demo portfolio must start in generator-share mode with the same golden-fixture results. The `consumptionMatrix` starts empty. Existing tests must not break.
- **Two matrices, one at a time.** The state holds both `matrix` (generator-share) and `consumptionMatrix`. The active mode determines which one the UI edits and which one the engine uses. `ALLOCATE_EVENLY` applies to the active matrix only.
- **Engine design.** The engine should accept an optional `allocationMode` on `EngineInput`. When `'consumption-share'`, the engine ignores `Generator.generationMWh` for sizing and instead computes each pair's supply from the generator's normalised shape (shape / Σshape) × target MWh (where target = pct/100 × consumer total demand). The downstream allocation and matching logic (windows, shape preservation, caps) is unchanged.
- **Generator utilisation in consumption-share.** Since the generator's library size is not used, `totalGenerationMWh` should be set to the total assigned volume, `allocatedMWh` to the volume the matching window lets through, and `unallocatedMWh` to the difference. Generator size never produces surplus, but clipped energy must still appear so the Sankey adds up to the assigned total.
- **Allocate evenly in consumption-share.** The brief says: each consumer gets 100 % split equally across generators. With 2 generators, each cell = 50 %. With 3 generators, each cell = 34/33/33 (integer shares summing to 100).
- **Score strip label.** When in consumption-share mode, the "Annual generation" strip item should change its label to "Assigned" (or "Total assigned") since the value no longer reflects a generator's inherent output.
- **Scenario file version.** Adding `allocationMode` and `consumptionMatrix` as optional fields on the existing version-1 format is simplest. `validateScenarioFile` should accept files without these fields and default to `'generator-share'` / empty matrix.
- **Consumer allocated-pct total.** This is a new element in consumption-share mode showing the sum of all generators' percentages for that consumer. In generator-share mode this element is not needed (the existing column totals show MWh and % of demand).
- **Sign-up flag.** Every e2e spec sets `localStorage.setItem('scenario-tool.signedUp', new Date().toISOString())` after `localStorage.clear()`.
- **Playwright webServer.** Config builds before serving; do not start a separate preview on 4173.
